# Проверка AI-рекомендаций в дни матчей (20–22 ноября 2026)

Решение владельца: АПЛ, Ла Лига, Бундеслига, Серия А; **не больше 20 платных вызовов**, **бюджет до
$10**, **без реальных ставок**. Цель — проверить работу рекомендаций в день матча (до этого все 20
анализов 10–11.11 были `NO_BET / early_forecast`: рекомендация даётся только в день матча). Выводов о
статистической точности по 20 матчам не делаем.

## Как запускается

Локально, на коде релиза `b6cf031`, с реальными football-data и Anthropic, с собственной историей
прогнозов и состоянием в отдельной папке (стенд и production не участвуют):

```sh
cd <корень репозитория на b6cf031 или release/miniapp-prod>; S=<папка состояния, 0700>; install -m 600 <ключ football-data> $S/football_key; install -m 600 <ключ Anthropic> $S/anthropic_key
PYTHONPATH=. python deploy/miniapp/ai_matchday_check.py $S select 2026-11-20 --per-league 2   # бесплатно: выбор матчей дня
PYTHONPATH=. python deploy/miniapp/ai_matchday_check.py $S run                                # платно: анализ выбранных
# 21.11: select 2026-11-21 --per-league 3 → run;  22.11: select 2026-11-22 → run (добирает до 5 на лигу)
PYTHONPATH=. python deploy/miniapp/ai_matchday_check.py $S settle   # после матчей (бесплатно): результаты из календарей
PYTHONPATH=. python deploy/miniapp/ai_matchday_check.py $S report   # критерии + таблица по матчам
```

- Только матчи этого дня (UTC), не позже чем за 60 мин до начала — данные после начала матча в анализ
  попасть не могут; отчёт повторно проверяет `dataUntil < generatedAt < kickoff` по каждой строке.
- Отбор разнообразный: в каждой лиге сначала новые типы матчей (топ-матч, фаворит дома, фаворит в
  гостях, равные, низ таблицы).
- Лимиты в коде: перед каждым анализом проверяется, что после него останется ≤ 20 вызовов и
  ≤ $10 даже в худшем случае (8 000 выходных токенов); иначе — остановка. Ожидаемо: ~$0,007 за анализ,
  ~$0,15 за все 20.
- По каждому матчу сохраняются: результат анализа целиком, время запроса и генерации, длительность,
  токены вход/выход, расчётная стоимость, ошибки и таймауты (`ledger.json`).

## Критерии успеха (заданы заранее)

**Обязательные (FAIL любого — проверка не пройдена):**

1. Доставка: проанализированы **20 разных матчей**, по всем есть вероятности (`ready`/`partial`;
   `insufficient` для этих лиг — промах); повтор понадобился не более чем одному матчу (повтор —
   отдельный разрешённый вызов в пределах 20).
2. Задержка: p95 полного запроса (данные + модель, ближайший ранг) ≤ 20 с; за весь прогон не более
   одного `timeout`, и тот исправлен повтором.
3. Расходы: ≤ 20 платных вызовов, ≤ $10.
4. Целостность данных — 100 % строк: `dataUntil < generatedAt < kickoff`; вероятности 1/X/2 в сумме
   99–101; ответ модели прошёл схему (факторы и причины только из разрешённых списков — иначе
   `bad_output`).
5. Логика дня матча — 100 % строк: причина «без ставки» никогда не `early_forecast`; если рекомендация
   есть, у неё нет `noBetReason`; рекомендации только в проверенных турнирах (все четыре лиги).
6. Сверка: после `settle` (не раньше чем через 3 ч после последнего матча) **все** проанализированные
   матчи проверены: сыгранные — `settled` со счётом основного времени, совпадающим с записью football-data;
   перенесённые — `pending`/`void`, не «выигрыш/проигрыш». До этого критерий не выполнен.

**Описательные (не критерии и не выводы о точности):** доля матчей с рекомендацией и без,
распределение рынков, сколько рекомендаций сыграло по факту, средняя предсказанная вероятность против
фактической частоты — в отчёте с пометкой «20 матчей — статистически незначимо».

## Результат

Отчёт `report` (JSON с критериями + таблица по матчам) прикладывается к production-preflight. Решение
владельца по качеству рекомендаций — отдельно; этот прогон проверяет работоспособность и корректность,
не прибыльность.
