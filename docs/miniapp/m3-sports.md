# M3: реальные спортивные данные Mini App

Статус на 2026-11-07. Блок «данные» реализован и проверен офлайн; живой вызов
выполнен 2026-11-07 (`miniapp.live_check`, 2 запроса): football-data.org вернул
8 реальных матчей PL и LaLiga на 7 ноября, нормализованных корректно (статусы,
время UTC, турниры; минута и статистика на free-плане отсутствуют — так и
показывается). AI-разбор реальных матчей (M3.2) реализован и проверен офлайн —
см. «AI-разбор (M3.2)»; живой вызов Claude ещё не выполнялся.

## Источники

| Вид спорта | Источник | Статус | Почему |
|---|---|---|---|
| Футбол | football-data.org v4 | **реализован** | 12 турниров бесплатно, включая PL и PD (текущий сезон); бот уже использует этот API |
| Теннис | — | не подключён | у API-Sports нет тенниса; у Live Tennis API бесплатный план без результатов, коммерческое использование не подтверждено |
| Баскетбол | — | не подключён | API-Sports Basketball: бесплатный план, по всей видимости, без текущего сезона (не проверено); ключа нет |
| MMA | — | не подключён | API-Sports MMA: то же |

Факты о провайдерах проверены по официальной документации 2026-11-07:

- football-data.org: free — 10 запросов в минуту; **счета и расписание с
  задержкой** (без задержки — «Free w/ Livescores», €12 в месяц); статистики и
  составов на free нет (статистика — платная надстройка); статусы SCHEDULED,
  TIMED, IN_PLAY, PAUSED, EXTRA_TIME, PENALTY_SHOOTOUT, FINISHED, SUSPENDED,
  POSTPONED, CANCELLED, AWARDED. Условия: обязательная подпись «Football data
  provided by the Football-Data.org API» (§7); логотипы и эмблемы не
  лицензируются (§9.2) — мы их не отдаём и не показываем. Источники:
  https://docs.football-data.org/general/v4/policies.html,
  https://www.football-data.org/pricing,
  https://docs.football-data.org/general/v4/lookup_tables.html,
  https://www.football-data.org/client/register (условия).
- API-Football (ключ бота `APIFOOTBALL_KEY`): free — 100 запросов в сутки и,
  по официальному руководству, только сезоны «год−4…год−2» (2022–2024), то
  есть текущего сезона на free нет. Страницы api-sports.io закрыты Cloudflare
  для автоматического чтения; факты — из официальных страниц через поиск,
  **частично не проверены**. Перед подключением: `GET /status` и
  `GET /fixtures?league=39&season=2025` с ключом.
- Mostbet (коэффициенты бота): доступ по IP из whitelist бота; Mini App его не
  использует. Поэтому у Mini App сейчас нет источника коэффициентов.

## Архитектура

```
браузер ──cookie-сессия M2──▶ /api/sports/*  (FastAPI Mini App)
                                  │  SportsService: проверка запроса, покрытие
                                  │  SportsCache: TTL по статусу, single flight, stale
                                  │  ProviderClient: квоты, таймаут, повторы, 429
                                  ▼
                       football-data.org (ключ только в env backend)
```

- `miniapp/sports/models.py` — отдельные модели: футбол (голы, минута), теннис
  (сеты/геймы), баскетбол (четверти + овертаймы), MMA (раунды, способ победы).
- `client.py` — фиксированный https-хост, пути без `..`/`//`; лимит в минуту и
  в сутки; ≤ 2 параллельных запроса; таймаут 8 с; повторы с backoff только для
  таймаутов и 5xx; 429 — без повтора, пауза по `Retry-After` /
  `X-RequestCounter-Reset`; при `X-Requests-Available-Minute: 0` пауза до
  сброса заранее. Ключ — только в заголовке, в логах его и URL нет.
- `cache.py` — одна загрузка на ключ: 1000 открытий одного матча = 1 запрос.
  При сбое отдаются последние данные с пометкой `stale` и исходным временем
  (до 6 часов), без данных — ошибка, не демо.
- `football_data.py` — нормализация; `service.py` — диапазоны, турниры,
  покрытие; `routes.py` — HTTP API.
- ID с namespace провайдера: событие `fd:<match id>`, турнир `fd:<code>`,
  команда `fd:team:<id>`. Одинаковые названия в разных турнирах не смешиваются.

### Обновление и кеш

| Данные | TTL кеша |
|---|---|
| день с live-матчем | 60 с |
| предстоящие | 15 мин |
| только завершённые | 6 ч |
| прошедший день, всё сыграно/отменено | 12 ч |
| матч не найден (404) | 15 мин |

На free-плане счёт и так приходит с задержкой; интерфейс прямо пишет «Счет
приходит от источника с задержкой» (`liveScores: "delayed"`). Обновление «каждую
минуту в реальном времени» не обещается. Счётчики квоты живут в процессе (один
воркер) и сбрасываются при перезапуске; запас дневного бюджета
(3000 при теоретических 14 400) это покрывает.

## HTTP API (все маршруты, кроме эмблем, требуют сессию M2)

| Метод и путь | Ответ |
|---|---|
| `GET /api/sports/coverage` | статус по каждому виду спорта, провайдер, турниры, возможности, атрибуция, расход квоты |
| `GET /api/sports/{sport}/tournaments` | турниры вида спорта + краткое покрытие |
| `GET /api/sports/{sport}/events?from=&to=[&tournament=]` | события в интервале (ISO-8601 с зоной, ≤ 48 ч, окно −30…+60 дней) |
| `GET /api/sports/event/{id}` | одно событие + турнир; 404, если нет |
| `GET /api/sports/{sport}/tournaments/{id}/calendar` | весь текущий сезон турнира (M3.3): турнир с эмблемой, даты сезона, текущий тур, матчи; 404 — не наш турнир |
| `GET /api/crests/{team\|competition}/{id}` | эмблема PNG с нашего домена (M3.3); публичный, без сессии; 404 — эмблему источник не давал |

Ошибки: 401 `unauthenticated`; 400 `bad_request` / `bad_range` /
`range_out_of_window` / `unknown_tournament` (квота не тратится); 503
`source_unavailable` + `reason` (`rate_limited`, `quota_exhausted`, `timeout`,
`upstream_error`, `bad_response`) с `Retry-After`. Детали матча по id, которого
не было ни в одном списке, стоят запроса к провайдеру — их не больше
`MINIAPP_SPORTS_UNKNOWN_LOOKUPS_PER_HOUR` в час.

## Что приходит из настоящего API (футбол)

Реально: команды (название, короткое название), турнир, начало (UTC), статус
(включая перенос, приостановку, отмену, присуждённый результат), счёт и счёт
первого тайма для live/finished/suspended, минута — если источник её прислал,
время получения и время последнего обновления у источника.

`null` / `unavailable`: статистика матча, составы, травмы, xG, владение,
удары, коэффициенты, вероятности. Ничего из этого не подставляется.

## Frontend

`VITE_DATA_MODE` при сборке: `demo` (по умолчанию для `npm run build`,
офлайн-фикстуры) или `real` (`BackendSportsDataProvider`). Образ стенда требует
явного `--build-arg VITE_DATA_MODE=real|demo`: режим запекается в бандл, и
переменная окружения работающего контейнера его не меняет. Real никогда не переключается на demo: ошибка —
это состояние ошибки с «Повторить». В real-режиме:

- нет пометок «ДЕМО»; внизу — дата, пояс и атрибуция провайдера;
- карточка матча: источник, время обновления, пометка о задержке и о
  данных из кеша;
- статусы «Перенесен», «Прерван», «Отменен», «Статус неизвестен» — никогда не
  «Скоро»; без минуты от источника — «Идет матч», а не «0'»;
- турниры приходят с backend; для PL и LaLiga — локальные логотипы (ассеты
  M1), для остальных — эмблема источника через `/api/crests/` (M3.3);
- вид спорта без источника: «Источник данных не подключен», демо-матчи не
  показываются;
- AI-разбор реального матча без подключённого AI: кнопки нет, экран — «AI-разбор пока не подключен».

## Турниры, календарь, короткие названия, эмблемы (M3.3)

- **Турниры.** По умолчанию все клубные турниры бесплатного плана с текущим
  сезоном: PL, PD, SA, BL1, FL1, CL, ELC, DED, PPL, BSA
  (`MINIAPP_FOOTBALL_DATA_COMPETITIONS`). EC и WC доступны, но их сезоны
  закончились — включать, когда начнутся. Список матчей дня — по-прежнему
  один запрос в день на все турниры, так что больше турниров не значит больше
  запросов.
- **Календарь.** Главная → «Турниры» → турнир; также ссылка с названия турнира
  на странице матча и из каталога при выбранном турнире. Backend один раз
  берёт весь сезон (`/competitions/{code}/matches`, ~150–400 матчей) и держит
  в общем кеше 15 минут (2 минуты, пока идёт матч). Матч, открытый из
  календаря, берётся из того же календаря (пока он свежий — без запросов;
  иначе календарь обновляется одним общим запросом), а не отдельным запросом
  по id — лимит на неизвестные id не обходится. Если источник прислал меньше
  матчей, чем указал в `resultSet.count`, календарь считается ошибкой. Экран группирует матчи по
  дням в часовом поясе пользователя и открывается на ближайшем дне с матчами;
  тур — если источник его прислал. Матчи с ещё неизвестными соперниками
  (будущие стадии плей-офф) не показываются; матч другого турнира или
  нечитаемая запись — ошибка всего календаря, а не тихий пропуск.
- **Короткие названия.** Из поля `shortName` источника (латиница, как в
  источнике: «Real Betis», «Man City», «Barça»). Небольшая таблица
  `SHORT_NAMES` в `football_data.py` исправляет несколько неудачных
  (опечатка «Shaktar», «Brighton Hove», «PAE AEK» и т. п.); длиннее 24
  символов — показывается полное. Полное название остаётся для поиска и
  подписи эмблемы.
- **Эмблемы.** Браузер не обращается к стороннему хосту: backend берёт
  картинку по URL, который сам источник положил в ответ, и отдаёт её с нашего
  домена (CSP остаётся `img-src 'self'`, IP пользователя не уходит третьей
  стороне). Только `https://crests.football-data.org/<имя>.png`, без
  редиректов и без заголовков авторизации; только PNG (проверка по сигнатуре),
  SVG отклоняется — с нашего домена он мог бы исполнить скрипт; до 300 КБ;
  тайм-аут 5 с; не больше 240 загрузок в минуту (холодный кеш: один экран — десятки эмблем); неудача запоминается на час;
  кеш в памяти ограничен 800 картинками и 32 МБ; не больше 200 ответов
  эмблем в секунду. Маршрут публичный (без сессии) и кешируется сутки — в
  браузере и на Cloudflare (`Cache-Control: public, max-age=86400`). Нет эмблемы или она не загрузилась —
  буква на круглой подложке, как раньше. Эмблемы турниров backend узнаёт из
  списка `/competitions` (один общий запрос в сутки в фоне; ответ страницы ждёт
  его не дольше 2 с; при ошибке — повтор не раньше чем через 15 минут, экран
  при этом не ломается); эмблемы команд — из ответов с матчами.
- **Известное ограничение (P2, отложено).** SVG-эмблемы источника не
  показываются — вместо них буква: отдавать SVG с нашего домена небезопасно, а
  серверная растеризация — новая зависимость. В данных PL, PD, BL1, CL
  (проверено 2026-11-08) все эмблемы PNG.
- **Лицензия эмблем.** Эмблемы — товарные знаки клубов и турниров;
  football-data.org отдаёт их в API, но права на публичное использование в
  продукте нужно проверить до публичного запуска. На тестовом стенде — ок.

## AI-разбор (M3.2)

Порядок решений — в Python, до любого вызова модели (`miniapp/ai/analysis.py`):

1. только предстоящий футбольный матч (иначе INSUFFICIENT `not_upcoming`);
2. проверенная база (`miniapp/ai/evidence.py`): последние 5 завершённых матчей
   каждой команды (форма W/D/L, очки, голы, дом/выезд) и строка таблицы —
   всё из football-data.org, посчитано в Python;
3. готовность — правило бота (`miniapp/ai/readiness.py`): без источника
   коэффициентов лучший уровень PARTIAL; меньше 3 завершённых матчей у любой
   команды — INSUFFICIENT (`no_verified_form`, `no_odds_source`), модель не
   вызывается;
4. модель (`MINIAPP_AI_MODEL`, официальный SDK `anthropic`, structured output
   JSON schema) получает только эти числа и возвращает **только** три целых
   процента и 2–4 ключа факторов из фиксированного списка (`home_form`,
   `away_form`, `home_goals`, `away_goals`, `home_table`, `away_table`).
   Свободного текста от модели нет: она не может приписать число не той
   команде или назвать травмы/составы/коэффициенты. Каждое предложение на
   экране — шаблон az/ru/en, заполненный проверенными цифрами этой команды;
5. ответ проверяется строго: сумма 100, без дублей, ключи только из списка,
   `*_table` — только если у команды есть строка таблицы; всё вне контракта
   отбрасывается (`bad_output`), не чинится.

Стоимость: кеш на 6 ч по (матч, хеш проверенных данных) — общий для всех
пользователей и языков, повторный запрос и присоединение к уже идущему бесплатны.
Личный лимит новых разборов в сутки (`MINIAPP_AI_PER_USER_DAILY`) и общий бюджет
вызовов (`MINIAPP_AI_DAILY_BUDGET`) хранятся в SQLite Mini App (таблица
`ai_usage`, UTC-сутки): переживают перезапуск, восстановление из бэкапа их не
обнуляет. Личный лимит и общий бюджет списываются одной транзакцией за одни
UTC-сутки (оба или ни один); отменённый запрос не теряет оплаченный вызов. Время:
поиск матча и сбор данных — общий дедлайн 20 с (без списания), один вызов
модели ≤ 60 с по настенным часам без ретраев; таблица запрашивается параллельно
с формой и ждётся ≤ 8 с; фронтенд ждёт AI-запрос 120 с (с учётом ожидания SQLite).
Матч не анализируется начиная с 5 минут до начала (`KICKOFF_MARGIN_S`), даже
если кеш ещё считает его предстоящим — ни новый вызов, ни ответ из кеша.
Турнирная таблица — необязательная часть базы: если она недоступна, разбор
строится по форме (без факторов `*_table`).
Отказ модели, тайм-аут, лимиты → `{"error":"ai_unavailable","reason":...}`
(429 для личного лимита, 503 иначе), без текста от провайдера.

UI: заголовок «Оценка вероятностей» (PARTIAL), «Что повлияло на оценку» —
выбранные моделью факторы, собранные из цифр; под ними проверенные цифры обеих
команд и компактная пометка об ограниченности данных.
Кнопка AI в real-режиме — только для предстоящего футбола и только когда
backend сообщает `ai.status = connected`.

## Живая проверка (не в pytest и не в CI)

```bash
MINIAPP_FOOTBALL_DATA_KEY=<ключ> miniapp/.venv/bin/python -m miniapp.live_check [YYYY-MM-DD]
```

Не больше двух запросов (день матчей, затем один матч), печатает только
нормализованные данные и счётчики квоты — без ключа и URL. Ключ берётся только
из `MINIAPP_FOOTBALL_DATA_KEY`, не из `.env` бота.

AI (один платный вызов Claude, не в pytest и не в CI):

```bash
MINIAPP_FOOTBALL_DATA_KEY=<ключ> MINIAPP_ANTHROPIC_API_KEY=<ключ> \
  miniapp/.venv/bin/python -m miniapp.ai.live_check
```
