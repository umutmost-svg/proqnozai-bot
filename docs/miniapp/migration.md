# Переход с Telegram-бота на Mini App: аудит, миграция, вывод бота

Подготовлено 2026-11-11. Ничего не выполнено на production. Каждый шаг с пометкой **[владелец]** или
**[prod]** — только по отдельному разрешению. Связанные документы: `production.md` (сервер, Cloudflare,
бэкапы, runbook), `ai-matchday-check.md` (проверка AI).

## 1. Функции бота и Mini App

| Функция бота (код) | В Mini App | Вывод |
|---|---|---|
| Регистрация: выбор языка, авто-имя (`/start`, `lang_`, `ob_`: виды спорта, опыт) | вход через Telegram, язык из Telegram или выбранный в профиле; онбординга нет | язык переносится (§3); `sports`/`experience` в Mini App не используются |
| Меню матчей: спорт → страна → лига → матч (`fm_*`, `/matches`) | главная, турниры (все, поиск), календарь, матч, таблица | есть |
| Текстовый прогноз Claude по матчу, уточняющий диалог (`forecast_`, `conversation`) | AI-разбор матча (свои данные, PARTIAL/INSUFFICIENT) + модель Dixon–Coles, «Быстрый прогноз» | замена есть; **AI-разбор — до проверки качества 20–22.11 выключен** (§6) |
| История прогнозов, оценка 👍/👎, повтор (`/history`, `fb_`, `repeat_`) | персональной истории нет; история модели и сверка результатов — общие | **пробел**: старая история не показывается, хранится в архиве бота |
| Сравнение команд (`/compare`) | матч: форма, таблица, очные встречи — по данным | частично |
| Профиль: серия, точность по отзывам (`/profile`), часовой пояс (`/tz`, `users.tz_offset`) | профиль: язык; время — по часовому поясу устройства | серия/точность — **пробел** (персональной истории нет); `/tz` не нужен |
| Live-подписки на матч и уведомления о событиях (`watch_`, `live_subscriptions`, `poller`) | нет | **пробел** (нужны исходящие сообщения бота) |
| Алерты изменения коэффициентов (`odds_alerts`, `check_odds_changes`) | нет; лента коэффициентов Mini App в этом релизе выключена | **пробел** |
| Ежедневный пуш неактивным в 10:00 по их часовому поясу (`daily_push`) | нет | **пробел** |
| Партнёры, промокоды, переходы (`partners_show`, `/promo`, `partner_clicks`, `promo_*`) | строка «Партнёры» в профиле без действия | **пробел — решение владельца** (монетизация) |
| Ссылки-редиректы на партнёров `/r/<partner>` в старых сообщениях (`dashboard.py` берёт адреса у воркера бота, `/partners`) | нет | **скрытая зависимость**: после остановки воркера бота уже отправленные ссылки дадут 404, если дашборд не держит кеш. Решение владельца: сохранить редиректы (дашборд + статическая таблица адресов) или сознательно вывести |
| Рассылки админа (`broadcasts`, `broadcast_scheduler`), дашборд (`dashboard.py`, `stats_server.py`) | админка Mini App — локальный пилот, не production | **пробел для операций**: после остановки бота рассылки и метрики бота замирают |
| Блокировка пользователя админом (`users.is_blocked`) | `MINIAPP_BLOCKED_USER_IDS` (вход 403 `not_allowed`, ничего не сохраняется; сессия заблокированного сразу перестаёт действовать) | переносится: id из `--blocked-out` в эту переменную (§3) |
| Языки az, ru, en, tr, **kz**, uz, **ar** | az, ru, en, tr, uz, pt-BR, es | **пробел**: kz и ar → язык из Telegram или ru |
| Экспорт коэффициентов Mostbet в Mini App (`run_odds_export`) | приёмник есть, в релизе выключен (`MINIAPP_ODDS_FEED_ENABLED=false`) | зависимости нет |

**Зависимости Mini App от процесса бота: нет.** Mini App не читает `bot.db`, не ходит к боту по HTTP, в режиме
Ed25519 не держит токен бота, лента коэффициентов выключена. Остановка polling-процесса Mini App не затрагивает.
Общее только: Telegram-аккаунт бота (кнопка/Main Mini App) и, при общем ключе, квота football-data.

**Что станет невозможно после остановки бота без замены:** ответы на `/start` и сообщения в чате, нажатия на
старые inline-кнопки (будут «крутиться»), уведомления, рассылки, промокоды. Рекомендация — §5 «лаунчер».

## 2. Данные: таблица соответствия (по схеме `db.py` и `miniapp/store.py`)

Цифры по строкам — после аудита копии (`deploy/migration/bot_db_audit.py`); схема ниже — по коду, не по догадке.

| Бот (`bot.db`) | Mini App (`miniapp.db`) | Перенос |
|---|---|---|
| `users.user_id` | `users.telegram_user_id` (PK) | да — идентичность; только положительные id |
| `users.username` | `users.username` | да (Telegram обновит при входе) |
| `users.display_name` | `users.first_name` | да (Telegram обновит при входе) |
| `users.lang` | `users.lang`, `lang_source` | да: az/ru/en/tr/uz; `lang_source='user'`, если язык выбран в боте (`is_registered=1`), иначе `telegram`; kz/ar → `ru`+`telegram` (при входе — по языку Telegram) |
| `users.joined_at` | `users.created_at` | да (UTC epoch) |
| `users.last_active` | `users.last_login_at` | да («последний визит», для метрик) |
| `users.is_blocked=1` | `MINIAPP_BLOCKED_USER_IDS` (env) | строки не создаются; id — в файл `--blocked-out` → переменная окружения до открытия всем |
| `users.is_registered, onboarding_done, sports, experience, total_requests, tz_offset` | — | нет соответствия; в архиве |
| `forecast_history` (тексты прогнозов, отзывы) | — (`ai_forecasts` — общие прогнозы модели, не по пользователям) | нет; архив |
| `requests`, `request_queue`, `conversation` | — | нет; архив (аналитика/служебное) |
| `live_subscriptions`, `odds_alerts`, `live_events_seen` | — | нет (функции нет) |
| `partners`, `partner_aliases`, `partner_clicks`, `promo_campaign`, `promo_claims`, `promo_pool` | — | нет (решение владельца, §7) |
| `broadcasts`, `_migrations` | — | нет |
| — | `sessions`, `consumed_init_data`, `ai_usage`, `ai_forecasts`, … | создаются Mini App |

Пользователь, не перенесённый заранее, всё равно войдёт: Mini App создаёт строку при первом входе по
подписанному Telegram id. Перенос сохраняет выбранный язык, дату регистрации и «последний визит» и даёт
счётчик пользователей с первого дня. Дубли исключены ключом `telegram_user_id`.

## 3. Миграция пользователей

Скрипты (`deploy/migration/`), тесты — `miniapp/tests/test_migrate_users.py` (6 тестов, офлайн):
- `bot_db_backup.py` — согласованная копия `bot.db`: онлайн внутри работающего контейнера бота (SQLite backup
  API шагами по 256 страниц, бот не останавливается) или при остановленном боте во временном контейнере на его
  томе. Проверка свободного места (2× БД+WAL + 50 МБ, иначе ничего не пишет), предел времени `MAX_SECONDS`
  (300 с), неудачная копия удаляется; `integrity_check`, число строк; 0600. Проверено локально: копия 40 МБ при
  параллельной записи — `integrity=ok`; таймаут — копия удалена. **[prod, разрешение]**
- `bot_db_audit.py` — только агрегаты по копии (без id, имён, текстов): пользователи, языки, активность,
  заблокированные, «битые» id, дубли, сироты.
- `migrate_users.py` — запуск в контейнере Mini App по копии (скрипт подаётся на stdin, в образ не входит):
  `docker exec -i -u miniapp <ctr> python - /data/migration/bot-copy.db /data/miniapp.db [--apply] < /opt/sporbot/migrate_users.py`.
  Сухой прогон по умолчанию — данные не меняет; `--apply` пишет одной транзакцией
  `INSERT … ON CONFLICT DO NOTHING`. **Политика:** существующая строка Mini App никогда не меняется (кто уже вошёл
  в Mini App, сохраняет её данные, в т. ч. язык); повторный запуск ничего не дублирует; проверка «все пригодные
  пользователи бота есть в Mini App» → `RESULT PASS` (входы во время прогона не ломают проверку). Команда
  проверена в контейнере образа `724cea5`: сухой прогон → `--apply` PASS → повтор `to insert 0`. Тесты: 8.

Порядок:
1. **[prod]** `docker exec -i <bot> python - < deploy/migration/bot_db_backup.py` → копия в томе бота;
   `docker cp` на хост → `scp` на машину владельца/в бэкап-хранилище (0600) → удалить копию из тома бота
   (`docker exec <bot> rm <файл>`). Проверить `integrity=ok`.
2. Аудит копии: `python3 deploy/migration/bot_db_audit.py <копия>` → таблица §2 с реальными числами.
3. Пробная миграция — изолированно (локально или на новом сервере во временном томе): сухой прогон →
   `--apply` → `RESULT PASS`; повторный `--apply` — `to insert 0`; выборочная проверка 10 id (только счётчики).
4. Проверка входа существующих пользователей: владелец (существующий id) входит — язык из бота, дата
   регистрации сохранена (тест `test_first_login_after_migration_keeps_choice_and_join_date`).
5. На production Mini App (после деплоя, до открытия всем): копия → том Mini App (`/data/migration/`, 0600) →
   сухой прогон → `--apply`.
6. **Финальная дельта при переключении:** новая копия бота → тот же `migrate_users.py --apply` (переносит только
   новых пользователей бота) **и заново `--blocked-out`** из этой же копии → `MINIAPP_BLOCKED_USER_IDS` = новый
   список → Redeploy Mini App (сессии заблокированных после первой копии сразу перестают действовать) →
   проверка: вход заблокированного id в логах `auth.rejected reason=blocked`. Изменения профиля старых
   пользователей после первой копии не переносятся намеренно (политика: существующая строка Mini App не
   меняется; Telegram обновит имя/username при входе).
   Сухой прогон данных не меняет; он пишет только файл `--blocked-out`, если его попросили, и SQLite может
   создать служебный `-shm` рядом с базой.
7. «Остановка записи в старую систему»: бот останавливается (§6, шаг 3), убедиться, что задач `bot` нет
   (`docker service ps` — 0 running), и **только потом** снимается финальная копия — так в ней все пользователи.

## 4. Новая архитектура

По `production.md`: отдельный дроплет 2 ГБ как Remote Server Dokploy; сборка на нём; том `sporbot-miniapp-data`;
Cloudflare (proxied, Origin Certificate, Transform Rule, rate limit); firewall только Cloudflare на 80/443;
Ed25519 без токена бота; отдельный ключ football-data; **ключа Anthropic на запуске нет** (AI-разбор выключен до
проверки 20–22.11; отдельный ключ и лимиты AI — при включении, `tech-debt.md`);
внешние бэкапы `backup-job.sh` + проверенное восстановление `restore-drill.sh`; мониторинг `/api/health`.
Публичный режим отличается от закрытого отсутствием `MINIAPP_ALLOWED_USER_IDS` (и в обоих нет ключа Anthropic) (сессии и вход —
те же); отдельный ключ football-data для публичного режима **обязателен**, не опция.

Для публичного режима rate limit Cloudflare по IP поднять: у мобильных операторов (CGNAT) один IP у многих
людей. Открытие приложения — ~5–10 запросов; Free: 300 запросов за 10 с на IP по `/api/`, вход дополнительно
ограничен приложением (10 входов в минуту на Telegram id).

## 5. Telegram после перехода

- **[владелец, BotFather]** Main Mini App = `https://<MINIAPP_DOMAIN>` (кнопка «Открыть» в профиле бота,
  прямая ссылка `t.me/<bot>?startapp`), Menu Button = Mini App (по умолчанию для всех).
- Прямая ссылка и профиль подписываются Telegram так же (Ed25519 для id бота) — проверка на всех клиентах.
- **Лаунчер (рекомендация).** После остановки старого бота `/start`, любое сообщение и старые inline-кнопки
  остаются без ответа. Минимальный процесс на сервере Mini App с токеном бота: на любое сообщение — одна
  локализованная фраза и кнопка «Открыть ProqnozAI», на любой callback — `answerCallbackQuery`. Без БД, без
  рассылок, без Claude. Отдельный контейнер (токен бота не попадает в контейнер Mini App). ~1 день с тестами.
  Без лаунчера достаточно кнопки меню и Main Mini App, но старые кнопки в чатах будут «крутиться».

## 6. Вывод старого бота из эксплуатации

Рекомендуемый безопасный вариант: **публичный запуск Mini App 15.11, старый бот работает параллельно до
проверки AI 20–22.11**, затем остановка. Причина: в окно 12–17.11 у валидированных лиг 2 матча (BSA, 14.11;
пауза на сборные), AI-разбор до проверки выключен, а бот пока закрывает текстовые прогнозы, уведомления и
промокоды. Две системы с разными БД не мешают друг другу.

Процедура (после финального разрешения):
1. Подтвердить: миграция `RESULT PASS`, Mini App работает (наблюдение ≥ 24 ч), открытие всем прошло.
2. **Гейт — редиректы `/r/<partner>` (§1)**, они живут через воркер бота. Без выбранного варианта бот не
   останавливается:
   - A «вывести»: владелец письменно принимает, что старые партнёрские ссылки в чатах дадут 404;
   - B «сохранить»: отдельная доработка `dashboard.py` до остановки — статическая таблица «имя → адрес»
     без обращения к воркеру, с тестом. Таблица строится **до остановки** из онлайн-копии (`partners` +
     `partner_aliases`) и ставится вместе с доработкой; после остановки (шаг 5) её сверяют с финальной копией и
     при расхождении обновляют. `dashboard` остаётся запущенным, `bot` останавливается. Проверка: несколько
     старых ссылок → 302 на адрес партнёра.
3. **[владелец]** Dokploy → `bot` → Autodeploy OFF (иначе push в `main` поднимет его снова) → Stop.
   Не Delete: том `proqnozai-db`, конфигурация, образ остаются.
4. Проверить: `docker service ls` — `bot` 0/0, `docker service ps bot` — ни одной задачи Running; рассылок в
   статусе `running/pending` нет (аудит копии п. 5); Telegram `getWebhookInfo` — вебхука нет.
5. **[prod]** Финальная копия `bot.db` **после остановки**: временный контейнер на томе
   (`docker run --rm -i -v proqnozai-db:<BOT_DB_DIR> -e BOT_DB_DIR=<…> <образ бота> python - < bot_db_backup.py`),
   `integrity=ok`, вне сервера; из неё — финальная дельта пользователей (§3, п. 6).
6. Mini App работает: `/api/health`, вход, прогнозы (smoke).
7. `dashboard` (HTTP-воркер бота) — Stop отдельно, после решения о метриках.
8. Хранение: том `proqnozai-db`, образ, конфигурация, копии `bot.db` — **не менее 30 дней** (срок — решение
   владельца), затем удаление только по отдельному разрешению.

**Откат с учётом расхождения данных.** После переключения новые пользователи и выбор языка живут только в
Mini App. Старый бот при повторном запуске их не знает, но не ломается: незнакомый пользователь проходит
`/start` заново. Откат = Start `bot` в Dokploy (том цел) + вернуть Menu Button/Main Mini App к прежним
значениям (записать их до шага 5 runbook). Данные Mini App не переносятся обратно (у бота нет для них полей);
пользователи, пришедшие после переключения, в боте регистрируются заново. Откат возможен, пока том
`proqnozai-db` не удалён.
