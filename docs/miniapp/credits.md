# Кредиты и MB ID (решения владельца 16.11.2026)

## Правила

- **Цена:** любой прогноз — быстрый (single), купон, AI-разбор — **10 кредитов**.
- **Списание только при генерации прогноза** и только при успехе: «нет ставки», «мало матчей», ошибка AI/источника,
  `insufficient` — бесплатно. Просмотр уже готового разбора (GET /api/ai/analysis) — бесплатно, как и раньше.
- Повтор того же прогноза тем же пользователем не списывается второй раз: AI — по матчу (`ai:<event_id>`), быстрый
  прогноз/купон — по UTC-дню и критериям (`quick:<day>:<mode>:<market>:<risk>:<size>:<tournaments>`).
- **Стартовые:** 100 кредитов каждому при первом обращении к кредитам, **включая уже существующих пользователей**.
- **Ежемесячные:** +50, не чаще раза в календарный месяц (UTC), при обращении, если баланс < 10.
- **Выключатель** `credits.enabled` в админке (Настройки), по умолчанию **выключен**: кредиты полностью скрыты от
  пользователей (нет раздела, нет ввода MB ID, `/api/credits` отвечает `{"enabled": false}`, счета не создаются),
  прогнозы бесплатны. Владелец включает сам.
- **Калькулятор депозитов** (экран «Кредиты»): кредиты начисляются за **сумму депозитов** у партнёра; курс по гео —
  таблица `credits.rates` в админке (страна ISO-2 или `*` → валюта → депозит на 1 прогноз). Страна зрителя — по
  CF-IPCountry за проверенным edge, не сохраняется. Без курсов калькулятор скрыт.
- Без кредитов (баланс < 10 при включённом выключателе): HTTP 402 `{"error":"no_credits","balance","cost"}`,
  в Mini App — экран «Кредиты» (баланс, когда придут ежемесячные, привязка MB ID).
- Дневные лимиты AI (на пользователя / на всех) остаются как защита бюджета.

## MB ID

- Пользователь вводит MB ID в Mini App (профиль/экран кредитов) → статус `pending`.
- Владелец лично подтверждает или отклоняет в админке (очередь «MB ID на проверку», с причиной, в журнал).
- Один MB ID не может быть у двух пользователей (pending или approved). Отклонённый можно ввести заново.
- Подтверждённый MB ID попадает и в `crm_external_ids` админки (таргетинг рекламы `mb_verified` / `mb_id_in`).
- Списание за AI-разбор — только если языковая модель реально сделала разбор (в т.ч. «без ставки»).
- Кредиты за действия в продукте партнёра — **отдельный этап**: загрузка выгрузки партнёра (CSV) в админке, начисление
  только на подтверждённые MB ID; формат файла и правила начисления — от владельца (ещё не получены).

## Где что живёт

- Баланс, журнал (append-only), купленные прогнозы, MB ID — в `miniapp.db` (списание атомарно там, где прогноз).
- AI-разбор: кредиты **резервируются до генерации** (`Credits.hold`) и возвращаются один раз (`settle`), если
  языковая модель не дала разбор (ошибка, `insufficient`, оценка только по рынку). Быстрый прогноз/купон —
  проверка до и списание после успешной выдачи (гонка → 402, прогноз не выдаётся).
- Админка пишет в `miniapp.db` напрямую (как уже делает для отзыва сессий), идемпотентно по ключу
  (`applied_commands`): начисление/списание/безлимит — в две фазы журнала (`requested` + `crm_credit_requests`
  → применение → `completed`, незавершённое добивается при старте); выключатель и курсы — после коммита настроек,
  по версии, и ещё раз при старте; решение по MB ID — для конкретной заявки (ID + время отправки), сначала в
  Mini App, потом копия в `crm_external_ids`. Ручная установка MB ID в карточке — только владелец.

## Принятые ограничения (аудит Codex)

- Если цены (единственный источник данных разбора) истекли ровно между генерацией и ответом, разбор отдаётся как
  `insufficient`, пользователь его не видит — резерв возвращается; расход на модель несёт сервис (редкий случай).
