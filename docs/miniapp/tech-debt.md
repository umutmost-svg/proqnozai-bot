# Mini App — технический долг

Сознательно принятые недоработки: что именно, почему принято и когда вернуться.

## Прогрев данных для AI-анализа (`fix/ai-evidence-warmup`)

Приняты владельцем 2026-11-11 (Codex P2):

- **Повторы фоновых запросов сезона при серии 5xx.** Прогрев календарей и прошлых сезонов
  (`sports/search.py`, `search_pacing`) рассчитан на ≤ 25% минутного лимита. Если провайдер отвечает
  5xx, клиент повторяет каждый запрос до трёх раз, и в такой серии фон может превысить эту долю.
  Резерв минуты для пользователей (`LOW_PRIORITY_RESERVE`) при этом проверяется на каждой попытке,
  поэтому пользовательские запросы не вытесняются. Вернуться, если в логах будут длинные серии
  `search.warm_skipped ... upstream_error`.
- **Сорванный прогрев прошлого сезона повторяется только со следующим обновлением календаря.**
  Если календарь уже в индексе поиска, а загрузка прошлого сезона не удалась (временная ошибка или
  исчерпан фоновый бюджет), прогрев вернётся к нему лишь при следующем обновлении календаря
  (`refresh_after_s`). AI-анализ пользователя при этом загрузит сезон сам (параллельно с календарём,
  когда в минуте есть запас).

## Release candidate `rc/stand-2026-11-11` — к согласованию

Найдено при интеграционном ревью Codex (APPROVE, P2) и живом прогоне; не исправлено, ждёт решения владельца:

- **Общий бюджет фоновой работы.** Прогрев таблиц, календарей с прошлыми сезонами, эмблем и расчёт
  результатов прогнозов (settlement) делят один фоновый слот и общий дневной потолок
  (`STANDINGS_WARM_DAY_SHARE`); `search_pacing` считает долю календарей и сезонов отдельно. При большом
  каталоге таблицы могут занять часть бюджета, рассчитанного на календари, и часть календарей/сезонов
  останется холодной до следующего прохода. Доля «≤ 25% минуты» выше относится к прогреву календарей,
  а не ко всей фоновой работе.
- **Settlement откладывается на время прохода прогрева календарей.** Пока идёт проход (включая паузы
  между загрузками, на Pro ~10–15 минут для 117 турниров), собственная загрузка календаря для расчёта
  результатов ждёт. Календари, загруженные самим прогревом, расчёт получает через слушателя, поэтому
  результаты не теряются, а приходят с задержкой.
- **Временные сбои хоста эмблем.** `crests.football-data.org` иногда не отвечает за 5 с: такая эмблема
  (если не помог флаг-заменитель) не показывается до часа (`failure_ttl_s`). В живом прогоне — 0–2 из
  109 эмблем турниров за прогон, каждый раз разные. Поведение было и до этого релиза.
