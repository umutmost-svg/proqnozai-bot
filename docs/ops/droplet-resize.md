# Ресайз production-дроплета `proqnozai-prod` до 4 ГБ RAM / 2 vCPU

Подготовлено 2026-11-12. **Не выполнено.** Выполняется только по отдельному разрешению владельца
(выключение сервера = перерыв бота).

## Что даёт и чего не даёт

- Тип в DigitalOcean: **Basic Regular, 2 vCPU / 4 GB** (`s-2vcpu-4gb`), опция **«Resize CPU and RAM only»** —
  диск остаётся 58 ГБ. Поэтому ресайз **обратим**: позже можно вернуться на меньший тариф.
- **IP 164.90.180.208 сохраняется**: публичный IPv4 закреплён за дроплетом, пока его не удалили; выключение
  и ресайз его не меняют. (Reserved IP не нужен.)
- Стоимость: около +$12 в месяц к текущему тарифу (точная цена — в панели при выборе).
- Перерыв: выключение → снимок → ресайз → загрузка → старт Docker-сервисов. По оценкам DigitalOcean при 11 ГБ
  занятого места: снимок **11–33 мин**, ресайз **~11 мин** (сервер может переехать на другой гипервизор), плюс
  выключение и загрузка. **Закладывать окно 60 минут без бота и без панели Dokploy**; 15–20 минут — лучший
  случай, не ориентир.
- Ресайз решает нехватку памяти **на этом сервере** (Dokploy 826 МБ + бот + запас). Он **не заменяет**
  отдельный сервер для Mini App: рекомендация `production.md` («Размещение») остаётся — сборка и работа
  Mini App на отдельной машине. Если владелец решит ставить Mini App сюда же, это отдельное решение с новым
  разбором рисков.

## План (по шагам, с ожидаемым результатом)

**Окно:** ночь по Баку, 04:00–05:00 (00:00–01:00 UTC) — меньше всего пользователей. В окно не должно быть
рассылки (таблица `broadcasts` пуста) и выкладок.

1. **За час — свежая копия БД бота** (`deploy/migration/bot_db_backup.py`, онлайн, без остановки) → зашифровано
   вне сервера, SHA-256 сверен. *Стоп:* `integrity` ≠ ok.
2. **Состояние «до»** (записать): `docker service ls` (все 1/1), время последней строки лога бота, `free -m`,
   ответ панели Dokploy.
3. **Штатное выключение по SSH:** `ssh root@164.90.180.208 'shutdown -h now'` — systemd останавливает Docker,
   контейнеры (бот, Postgres Dokploy) закрываются штатно. Ждать в панели статус **Off** (до 5 минут). Только если
   не выключился — Power → Turn off в панели (жёсткое выключение, риск для Postgres/SQLite). Не «Power cycle».
4. **Снимок — обязательно:** Snapshots → Take snapshot выключенного дроплета, имя
   `proqnozai-prod-pre-resize-<дата>`. Дождаться статуса готовности и записать имя. Это единственная точка
   возврата **всего** сервера (Dokploy Postgres, конфигурация, тома), копия шага 1 — только БД бота.
   Стоимость ≈ $0,06/ГБ·мес за занятое место (≈ $0,7/мес). *Стоп:* снимок не создался → не делать ресайз,
   включить дроплет обратно.
5. **Resize:** Droplet → Resize → **CPU and RAM only** → Basic Regular **2 vCPU / 4 GB** → Resize. Дождаться
   завершения.
6. **Включить:** Power → Turn on.
7. **Проверка (до 10 минут после загрузки):**
   - `free -m` — ~3 900 МБ; `nproc` — 2; `df -h /` — 58 ГБ (диск не изменён); IP по-прежнему 164.90.180.208;
   - `docker service ls` — все сервисы 1/1 (как в шаге 2), `docker ps` — бот `Up`;
   - `timedatectl` — `NTPSynchronized=yes`; `docker info` — Swarm active, manager;
   - логи бота: новые строки после загрузки, 0 `ERROR/Traceback`, 0 `Conflict: terminated by other getUpdates`;
     контрольное сообщение, отправленное боту во время простоя, получило ответ (в пределах 24 ч хранения);
   - интеграция MB: строки `odds_export`/Mostbet в логах без ошибок;
   - Dokploy: панель открывается (домен или SSH-туннель), приложения видны; доступность :3000 снаружи — та же,
     что до ресайза (с внешней машины, например ноутбука владельца: `sh deploy/miniapp/origin-check.sh --ports 164.90.180.208 none 3000`
     до и после; IPv6 у дроплета нет);
   - Traefik: HTTPS-маршруты (домен панели/дашборда, если есть) отвечают, сертификат тот же
     (`openssl s_client … | openssl x509 -noout -issuer -enddate`);
   - cron: `/etc/cron.d` и crontab root без изменений;
   - дашборд (`httpworker`) отвечает;
   - контрольный `/start` у бота с телефона владельца.
   *Стоп:* сервис не поднялся за 10 минут после загрузки → `docker service ps <имя> --no-trunc` и логи,
   решение по ситуации (см. «Откат»). Откат на снимок — крайняя мера: всё, что записано после снимка
   (новые пользователи бота, данные Dokploy), будет потеряно; решение принимает владелец.
8. **Отчёт:** фактическое время простоя, `free -m` до/после, результаты шага 7.

## Откат

- Сервисы не поднялись, сервер жив: для `dokploy`, `dokploy-postgres`, `httpworker` —
  `docker service update --force <имя>`. **Для бота так нельзя** (`start-first` = два процесса бота на одной
  SQLite): только `docker service scale <бот>=0` → дождаться, что `docker service ps <бот>` не показывает
  ни одной задачи Running → `docker service scale <бот>=1`.
- Сервер не загружается: восстановить снимок шага 4 **на этот же дроплет** (Droplet → Backups & Snapshots →
  Restore) — IP и метаданные сохраняются. Создание **нового** дроплета из снимка IP не сохраняет.
- Вернуть 2 ГБ: снова выключение → Resize до прежнего тарифа (возможно, потому что диск не увеличивали).
- Данные бота (только если база повреждена; решение владельца — всё записанное после копии шага 1 пропадёт):
  1. расшифровать копию шага 1 на машине владельца, сверить SHA-256 с манифестом, `PRAGMA integrity_check` = ok;
  2. перед любыми действиями подтвердить путь — по **сервису** (работает и при остановленном контейнере):
     `docker service inspect <сервис бота> --format '{{range .Spec.TaskTemplate.ContainerSpec.Env}}{{println .}}{{end}}' | grep '^BOT_DB_DIR='`
     и `docker service inspect <сервис бота> --format '{{range .Spec.TaskTemplate.ContainerSpec.Mounts}}{{.Source}} -> {{.Target}}{{end}}'`
     — ожидается `BOT_DB_DIR=/app/data` и `proqnozai-db -> /app/data` (так на 2026-11-12); если иначе —
     использовать фактические значения (`<сервис бота>` — имя из `docker service ls`, `proqnozai-proqnozaibot-…`);
  3. `docker service scale <сервис бота>=0` → дождаться, что `docker service ps <бот>` не показывает задач Running;
  4. загрузить копию на сервер (`scp`, 0600) и во временном контейнере на томе `proqnozai-db`
     (`docker run --rm -v proqnozai-db:/app/data -v /root/restore:/in:ro <образ бота> sh -c '…'`) переложить
     текущие `bot.db`, `bot.db-wal`, `bot.db-shm` в `/app/data/broken-<дата>/`, скопировать копию как `bot.db`;
  5. `docker service scale <бот>=1` → логи без ошибок, `/start` отвечает; удалить `/root/restore`.

## Чего не делать

- Не выбирать «Disk, CPU and RAM» — это необратимо (меньший тариф после него недоступен).
- Не использовать Power cycle / Destroy / Rebuild.
- Не менять в это окно firewall, Dokploy-приложения и переменные окружения — по одному изменению за раз.
