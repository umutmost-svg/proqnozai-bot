# Ресайз production-дроплета `proqnozai-prod` до 4 ГБ RAM / 2 vCPU

Подготовлено 2026-11-12. **Не выполнено.** Выполняется только по отдельному разрешению владельца
(выключение сервера = перерыв бота).

## Факты (проверено 2026-11-12, только чтение)

| Параметр | Сейчас |
|---|---|
| Дроплет | `proqnozai-prod`, регион fra1, публичный IPv4 164.90.180.208 |
| CPU / RAM / диск | 2 vCPU / 1 967 МБ / 58 ГБ (занято 11 ГБ) — vCPU уже 2, меняется только RAM |
| Нагрузка | load average ≈ 0; RAM: доступно ~550 МБ, swap нет |
| Сервисы (Swarm) | `dokploy`, `dokploy-postgres`, `proqnozai-proqnozaibot-…` (бот), `proqnozai-httpworker…` (дашборд), Traefik — все 1/1 |
| Docker | `enabled` в systemd: после загрузки поднимается сам, Swarm восстанавливает сервисы |
| Бот | `app.run_polling()` без `drop_pending_updates`: сообщения, пришедшие во время простоя, Telegram хранит до 24 ч и отдаёт после старта — не теряются |
| Копия БД бота | 2026-11-11 21:43 UTC, `integrity=ok`, зашифрована, вне сервера, восстановление проверено |

## Что даёт и чего не даёт

- Тип в DigitalOcean: **Basic Regular, 2 vCPU / 4 GB** (`s-2vcpu-4gb`), опция **«Resize CPU and RAM only»** —
  диск остаётся 58 ГБ. Поэтому ресайз **обратим**: позже можно вернуться на меньший тариф.
- **IP 164.90.180.208 сохраняется**: публичный IPv4 закреплён за дроплетом, пока его не удалили; выключение
  и ресайз его не меняют. (Reserved IP не нужен.)
- Стоимость: около +$12 в месяц к текущему тарифу (точная цена — в панели при выборе).
- Перерыв: выключение → ресайз (обычно 1–3 мин для CPU/RAM) → загрузка → старт Docker-сервисов.
  **Ожидаемо 5–10 минут без бота и без панели Dokploy.**
- Ресайз решает нехватку памяти **на этом сервере** (Dokploy 826 МБ + бот + запас). Он **не заменяет**
  отдельный сервер для Mini App: рекомендация `production.md` («Размещение») остаётся — сборка и работа
  Mini App на отдельной машине. Если владелец решит ставить Mini App сюда же, это отдельное решение с новым
  разбором рисков.

## План (по шагам, с ожидаемым результатом)

**Окно:** ночь по Баку, 04:00–05:00 (00:00–01:00 UTC) — меньше всего пользователей. В окно не должно быть
рассылки (таблица `broadcasts` пуста) и выкладок.

1. **За час — свежая копия БД бота** (`deploy/migration/bot_db_backup.py`, онлайн, без остановки) → зашифровано
   вне сервера, SHA-256 сверен. *Стоп:* `integrity` ≠ ok.
2. **Состояние «до»** (записать): `docker service ls` (все 1/1), время последней строки лога бота, `free -m`,
   ответ панели Dokploy.
3. **Мягкое выключение** с консоли DigitalOcean (Droplet → Power → **Turn off**) — это ACPI-выключение, Docker
   останавливает контейнеры штатно. Ждать статус Off. *(Альтернатива — `shutdown -h now` по SSH; не
   «Power cycle».)*
4. **Снимок (по желанию, +5–10 мин простоя):** Snapshots → Take snapshot выключенного дроплета — точка
   возврата всего сервера (~$0,06/ГБ·мес за занятое место, ≈ $0,7/мес). Рекомендуется: это первый ресайз
   production.
5. **Resize:** Droplet → Resize → **CPU and RAM only** → Basic Regular **2 vCPU / 4 GB** → Resize. Дождаться
   завершения.
6. **Включить:** Power → Turn on.
7. **Проверка (до 10 минут после загрузки):**
   - `free -m` — ~3 900 МБ; `nproc` — 2; `df -h /` — 58 ГБ (диск не изменён); IP по-прежнему 164.90.180.208;
   - `docker service ls` — все сервисы 1/1 (как в шаге 2), `docker ps` — бот `Up`;
   - логи бота: новые строки после загрузки, 0 `ERROR/Traceback`, 0 `Conflict: terminated by other getUpdates`;
     сообщения, отправленные боту во время простоя, получили ответ;
   - интеграция MB: строки `odds_export`/Mostbet в логах без ошибок;
   - Dokploy: панель открывается (домен или SSH-туннель), приложения видны;
   - дашборд (`httpworker`) отвечает;
   - контрольный `/start` у бота с телефона владельца.
   *Стоп:* сервис не поднялся за 10 минут → `docker service ps <имя> --no-trunc` и логи; если не чинится
   быстро — откат.
8. **Отчёт:** фактическое время простоя, `free -m` до/после, результаты шага 7.

## Откат

- Сервисы не поднялись, сервер жив: перезапуск конкретного сервиса через Dokploy (Redeploy не нужен —
  Restart), либо `docker service update --force <имя>`.
- Сервер не загружается: восстановить снимок шага 4 (Snapshots → Restore) — IP сохраняется у этого же
  дроплета.
- Вернуть 2 ГБ: снова выключение → Resize до прежнего тарифа (возможно, потому что диск не увеличивали).
- Данные бота: копия шага 1 (`docs/miniapp/migration.md` §3 — порядок восстановления).

## Чего не делать

- Не выбирать «Disk, CPU and RAM» — это необратимо (меньший тариф после него недоступен).
- Не использовать Power cycle / Destroy / Rebuild.
- Не менять в это окно firewall, Dokploy-приложения и переменные окружения — по одному изменению за раз.
