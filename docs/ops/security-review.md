# Mini App API — ревью безопасности перед публичным запуском

Дата 2026-11-13. Объект — backend `miniapp/` на коммите **a33a6b0** (`release/miniapp-prod`, то, что в
production), только чтение кода; сеть и сервер не использовались. Угрозная модель — **публичный** режим: любой
владелец валидного Telegram initData, в том числе пачка «одноразовых» аккаунтов. Исправления — ветка
`fix/miniapp-security` от a33a6b0 (см. §3).

## 2. Проверено и в порядке

- **initData (Ed25519, прод):** официальные ключи Telegram (prod/test), строка подписи привязана к `bot_id`;
  подписаны все поля кроме `hash`/`signature`; строгий разбор (дубликаты, %-escape, CR/LF, лимиты 8 КиБ / 4096
  символов); `user` — целый id, не бот; свежесть 300 с, будущее ≤ 30 с; в режиме Ed25519 токена бота в контейнере
  нет (старт с токеном — ошибка), обязательны CSRF-секрет и `bot_id`. HMAC-режим — `compare_digest`.
- **Сессии:** 256-битный токен, в БД — только SHA-256; cookie `__Host-`, Secure, HttpOnly, SameSite=None +
  Partitioned; `none` без Secure не стартует; серверный срок, ≤ 5 на пользователя, logout/logout-all
  атомарно «сжигают» запуск; смена аккаунта отзывает старую сессию.
- **Allowlist/blocklist:** проверяются и при входе (данные отвергнутых не сохраняются), и на **каждом** запросе
  — убранный id теряет сессию сразу. Меняются только через env (Redeploy).
- **CSRF:** точный `Origin` на каждом POST (нет/`null` — отказ) + `X-CSRF-Token` = HMAC(secret, token)
  (`compare_digest`); строгий JSON (тип, точный набор ключей, без дубликатов, лимит размера и для chunked).
  GET не меняет состояние и не тратит деньги.
- **X-Edge-Auth:** middleware на всех маршрутах (включая статику и 404), `compare_digest`; в production без
  секрета старт невозможен (≥ 32 печатных ASCII); исключение — только `GET /api/health` (ok/unavailable, кэш 5 с).
- **Квота AI:** резерв под `asyncio.Lock` + `BEGIN IMMEDIATE` (пер-пользовательский и глобальный счётчики
  вместе) — гонки не превышают квоту; переживает рестарт; сутки по UTC; ≤ 2 платные попытки на ключ анализа,
  попытка записывается до вызова; повтор анализа — из кэша без списания.
- **Odds push:** HMAC-SHA256 над `timestamp.body`, `compare_digest`, ±120 с, nonce, 512 КиБ / 600 строк,
  30/мин только для подписанных; без секрета маршрут → 404.
- **Admin:** только CLI (`admin.py`), HTTP-маршрута нет; не работает от root; выводит только счётчики.
- **Логи:** access-log uvicorn выключен (query string не пишется); ошибки клиенту — `{"error":"internal",
  "request_id"}`; в логе — тип исключения и `file:line`, коды причин и user id; initData, токены, имена не
  пишутся; секреты исключены из `repr` настроек; OpenAPI/docs выключены.
- **Заголовки:** строгий CSP без `unsafe-inline`, `frame-ancestors https://web.telegram.org`; SVG — с
  sandbox-CSP; nosniff, no-referrer, Permissions-Policy, HSTS (prod), `no-store` на API; CORS-middleware нет.
- **SQL:** все запросы параметризованы (f-строки — только константы модуля). **Статика/гербы:** StaticFiles
  (без traversal и symlink), `/api` не проваливается в статику; гербы — только из выученного allowlist.
- **SSRF:** загрузка гербов только HTTPS на `crests.football-data.org` по строгому шаблону пути, без
  редиректов, с лимитом размера и проверкой сигнатуры/безопасного SVG; клиент провайдера редиректы не следует.
- **Память:** все кэши, ключуемые вводом пользователя, ограничены (2000 / 50k / 10k / 5000).
- **Контейнер:** сброс root через `setpriv` + no-new-privs, один воркер, proxy-заголовки игнорируются.

## 3. Ветка `fix/miniapp-security` (от a33a6b0)

- `miniapp/settings.py`: `MINIAPP_ALLOWED_USER_IDS` задана, но пуста/из пробелов → `SettingsError`
  («list user ids, or remove the variable to open the app»); пустой `MINIAPP_BLOCKED_USER_IDS` по-прежнему
  допустим; `environment=production` + `telegram_env=test` → `SettingsError`.
- `miniapp/app.py`: при старте `startup access_mode=allowlist(N)|public blocked=M` (без самих id).
- Тесты: `tests/test_closed_launch.py` (пустое/пробелы/`" , "` — ошибка, отсутствие — public, лог режима,
  пустой blocklist), `tests/test_auth_ed25519.py` (test-DC запрещён в production).
- Совместимость с текущим продом: `dokploy_deploy.py` всегда задаёт непустой `MINIAPP_ALLOWED_USER_IDS`
  (id владельца, проверка `isdigit`), `MINIAPP_TELEGRAM_ENV` не задаётся (= production) — поведение прода не
  меняется. Выкладка — отдельным разрешением вместе с ближайшим релизом Mini App.

## 4. Что сделать до этапа «открыто всем»

2. F5 — ужесточить лимит входа; F8 — пересмотреть правило Cloudflare (`production.md` §2).
3. Включение odds-фида — только с WAF-правилом по IP бота (F7).
